# Native float submission filter: MAIN integration, 2026-10-30

Source parent: 3e202333; includes release-batch 2f24b31e and accepted ConsumedRecordCopy. Steam remains the accepted 4a26aabd DLL (SHA 3FDEB05CD94D6FC4E14C6C446A2859DA5F9A9E832AF5348D4602E4A7EF03C3EA). No deployment or gameplay measurement occurred for this integration.

## Actual change

NativeSubmissionFilter is a separate startup-only INI switch, default 0. The native VS/PS float hooks still run all raw recorder, camera, stereo and history operations. Immediately before native submission, they may omit an entire packet only when every final register bit equals a previously successful D3D_OK upload on this device/owner thread. They compare their own copied bytes, not application pointers, shader hashes or raw pre-eye matrices. Ordinary forwarded calls retain the original native pointer, register range and HRESULT. INTZ, texture/depth bind ordering and all existing replay optimizations are unchanged.

RecEmitData supplies a packet only after a complete successful owned capture under the existing recorder lock. The packet copies bytes into caller-thread storage immediately; arena reallocation, subsequent writes and caller lifetime do not escape that boundary. Stereo completion replaces that packet with the final local eye-adjusted array. A missing/failed capture forwards native and discards knowledge. No new read of the application pointer, permission query, RPM call, driver query, fence, per-draw disk log, resource reference or allocation is added by the filter. Thread-local cache storage is bounded (~13 KB per participating thread); exact counters join the existing sparse TrueStereo status log.

The existing ConsumedRecordCopy/DirectCopy guard fallback is unchanged. A failed recorder copy cannot authorize native elision. Its unresolved concurrent PAGE_GUARD/protection-restoration risks remain; these tests do not establish blanket runtime memory safety. No source page cache or inferred lifetime is introduced.

## Ownership/invalidation

- A real foreign mutation thread permanently denies filtering. First ownership uses CAS; steady owner mutations use loads only.
- Any native Begin/Create/EndStateBlock outside the mod-owned raw region permanently denies filtering, because legacy StateBlockHook=0 cannot prove later Apply interception. Even failed creation is conservatively denied. Only the exact internal snapshot creation is excluded through a one-shot token consumed BEFORE entering the native driver. Callback/raw-scope status alone is insufficient: recursive application creation cannot inherit that exemption.
- Device QueryInterface preserves the exact HRESULT/output/refcount. An unknown interface or a distinct device alias permanently denies filtering before the application receives it. Same-pointer IUnknown/Device9/Device9Ex identity is admitted. Failure to install this gate denies filtering. No guessed vendor vtable patch is used.
- Software vertex processing selection permanently denies filtering: mixed-processing register-bank identity is not inferred. A replacement device also denies it, including a shared-vtable call on another device before its HookDevice return: every filtered float entry checks the published device identity.
- Full raw VrFrame processing has a nested bypass at both edges, covering snapshots, replay, overlays and restoration. Reset/ResetEx invalidate both before and after native Reset. Every original device Present path invalidates on entry. Tentacle-scoped raw VS writes/restores invalidate before touching the float bank.
- Native driver callbacks invalidate late publication; no recorder lock surrounds native setters. An uncaptured forward has the same reentry protection. Non-D3D_OK writes never certify bits. Denial survives configuration/reset and requires a new process to retry.

This is a conditional optimization, not proof that the game will admit it. If real gameplay creates an opaque StateBlock or exposes an uncontrolled interface, enabled=0 and denied bits explain why; do not clear that denial to chase a gain. ReplayBufferVersions and DirectRecordCopy remain quarantined OFF.
